# WaveFit — PWA Architecture

This document describes the **current PWA architecture** of the WaveFit frontend (Workbox service worker, build pipeline, offline capabilities). It is a stable engineering reference.

---

## 1. Overview

WaveFit uses **Workbox** as the only service worker (SW). `@angular/service-worker` is **not** used.

| Aspect       | Workbox SW                                                                |
| ------------ | ------------------------------------------------------------------------- |
| Config       | `workbox-config.js` + `src/sw.js`                                         |
| Generated by | `workbox injectManifest` (post-build)                                     |
| Output       | `dist/wave-fit/browser/sw.js`                                             |
| Workbox code | Loaded at runtime via `importScripts` from the **Google Workbox CDN** (pinned to `7.0.0`); `workbox-sw` is not bundled with the app |
| Role         | Precaching + advanced caching + GraphQL IndexedDB cache + Background Sync |

> The SW depends on the Workbox CDN at runtime (`src/sw.js` line 1), so the service-worker code itself requires a network connection the first time it is fetched/executed.

## 2. Build Pipeline

`npm run build` executes:

```bash
ng build                     # Angular build
workbox injectManifest       # Injects the precache manifest into src/sw.js
```

- Takes `src/sw.js` (source) and the `self.__WB_MANIFEST` marker.
- Scans `dist/wave-fit/browser/` with the patterns from `workbox-config.js`.
- Replaces `self.__WB_MANIFEST` with the real build file list and emits `dist/wave-fit/browser/sw.js`.

```js
// workbox-config.js
module.exports = {
    globDirectory: 'dist/wave-fit/browser',
    globPatterns: ['**/*.{js,css,html,png,svg,ico,webmanifest,ttf,woff,woff2}'],
    globIgnores: ['**/sw.js'],
    swSrc: 'src/sw.js',
    swDest: 'dist/wave-fit/browser/sw.js',
    maximumFileSizeToCacheInBytes: 5 * 1024 * 1024, // 5MB
};
```

## 4. Custom Service Worker (`src/sw.js`)

### 4.1 Precaching

```js
precacheAndRoute(self.__WB_MANIFEST || []);
```

On `activate` the SW calls `self.clients.claim()` so it controls already-open pages. A global `fetch` listener logs every request (`[SW FETCH]`) to the console; this is diagnostic noise and has no functional effect.

### 4.2 Caching strategies

| Resource         | Strategy                   | Cache name | Details                                          |
| ---------------- | -------------------------- | ---------- | ------------------------------------------------ |
| Images           | `CacheFirst`               | `images`   | max 60 entries, expires 30 days                  |
| Fonts            | `CacheFirst`               | `webfonts` | max 20 entries, expires 1 year                   |
| Navigation (SPA) | `NetworkFirst` + fallback  | —          | Offline fallback to precached `index.html`       |
| GraphQL (POST)   | `NetworkFirst` + IndexedDB | —          | Caches responses for **all non-mutation queries** |

### 4.3 Navigation fallback (SPA)

```js
registerRoute(
    ({ request }) => request.mode === 'navigate',
    async ({ request }) => {
        try {
            return await fetch(request);
        } catch (error) {
            const cachedResponse =
                (await caches.match('/index.html')) || (await caches.match('index.html'));
            if (cachedResponse) return cachedResponse;
            throw error;
        }
    },
);
```

### 4.4 GraphQL IndexedDB caching

The SW intercepts **every** `POST /graphql` request. Mutations (any body whose `query` contains `mutation`) and the `Warmup` heartbeat are **bypassed** and sent straight to the network. Every other (named) query is cached in IndexedDB (`WaveFitDB` / `graphqlCache`) keyed by `JSON.stringify({ operationName, variables })`:

```text
Flow: parse body → skip if mutation/Warmup → try network → store {data} in IndexedDB → on failure return cached data → else 503 "Sin conexión y sin caché disponible" (fatal parse → 500 "SW Fatal Error")
```

**Known current behavior**: the `GRAPHQL_WHITELIST = ['GetExercises', 'Me']` constant in `src/sw.js` is **defined but unused** — it does not filter caching. The actual caching filter is "not a mutation and not `Warmup`". This is documented as-is; treat the whitelist as dead code.

The GraphQL cache hit/miss responses are synthesized locally with `Content-Type: application/json` (200 with `{data}` on hit, 503 with a Spanish error message on miss).

**IndexedDB object stores created by the SW (`DB_VERSION = 31`):**

| Store              | Key        | Purpose                                   |
| ------------------ | ---------- | ----------------------------------------- |
| `graphqlCache`     | `cacheKey` | Cached GraphQL query responses            |
| `pendingMutations` | `id`       | Pending mutations (offline-write support); indexes `operationName`, `status` |
| `authUser`         | `id`       | Authenticated user data                   |
| `exercises`        | `id`       | Exercise cache                            |
| `routines`         | `id`       | Routine cache                             |
| `plans`            | `id`       | Plan cache                                |
| `tracking`         | `id`       | Tracking/week-log cache                   |

On the app side, Dexie's `WaveFitDB` (`IndexedDbStorageService`, schemas at versions 2–4) opens the **same** database (`WaveFitDB`) and additionally declares the `dayLogs` store. The two sides use diverging version numbering (Dexie `version(4)` vs SW `DB_VERSION 31`) — this is the current state and a known friction point.

### 4.5 Skip waiting

```js
self.addEventListener('message', (event) => {
    if (event.data && event.data.type === 'SKIP_WAITING') {
        self.skipWaiting();
    }
});
```

## 5. Service Worker Registration

In `src/main.ts`, registered **only in production**:

```ts
if ('serviceWorker' in navigator && environment.production) {
    import('workbox-window').then(({ Workbox }) => {
        const wb = new Workbox('/sw.js');
        wb.addEventListener('installed', (event) => {
            if (event.isUpdate) {
                if (confirm('Nueva versión disponible. ¿Deseas actualizar?')) {
                    window.location.reload();
                }
            }
        });
        wb.register().catch((err) => {
            console.error('Service Worker registration failed:', err);
        });
    });
}
```

On user acceptance it reloads and sends `SKIP_WAITING`.

## 6. Offline Capability Summary

| Functionality                  | Online | Offline                             |
| ------------------------------ | ------ | ----------------------------------- |
| Initial app load               | ✅     | ✅ From precache                    |
| Route navigation               | ✅     | ✅ Serves `index.html`              |
| Images / Fonts                 | ✅     | ✅ From cache                       |
| GraphQL reads (non-mutations)  | ✅     | ✅ From IndexedDB (per-operation)   |
| Writes (create/update, etc.)   | ✅     | ✅ Optimistic + queued in `pendingMutations`, replayed by `SyncQueueService` on reconnect |

The frontend **offline-first layer** (for writes) lives in `SyncQueueService` + `IndexedDbStorageService`; see the [pwa-offline Spec](../../sdd/pwa-offline/spec.md).
